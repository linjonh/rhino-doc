# 配置


---
## 优化级别

目前支持以下优化设置：

|    |   |
|:---|:--|
|  -1  | 始终使用解释模式。编译时间最小化，但运行时性能较差。不生成类文件，这可能根据您的系统改善内存使用情况。解释模式的另一个好处是，解释器对递归函数执行尾调用消除。如果您的代码使用`Continuation`对象，则必须使用此优化级别<br/><br/>如果无法使用优化包，则优化将表现为始终为 -1 |
|  0  | 不执行任何优化。字节码编译器在此模式下运行最快，但生成的字节码效率较低 |
|  1-9  | 执行所有优化。进行简单数据和类型流分析，以确定哪些JavaScript变量可以分配到Java虚拟机寄存器，以及哪些变量仅用作Numbers。本地公共子表达式会被折叠（目前这仅适用于属性查找，但在未来可能会有更多的表达式优化）。所有本地变量和参数都分配到Java虚拟机寄存器。函数调用目标基于源代码中使用的名称进行推测性缓存，以便调度可以直接执行，等待运行时确认实际目标。参数作为Object/Number对传递，以减少转换开销 |

_注意事项：_

- 某些语言功能（对`eval`的间接调用，对函数对象的`arguments`属性的使用）在更高优化级别下之前不受支持。这些功能已从ECMA语言中移除，因此更高优化级别现在符合标准。
- 未来版本可能会将更激进的优化分配到更高的优化级别。为了与未来的版本兼容，使用第1级。为了实现最大优化，使用第9级，但在升级到新版本时请重新测试您的应用程序。
- 脚本是在编译时间而不是执行时间进行优化。因此，如果脚本以上下文的`optimizationLevel`设置为1进行编译，它将会以这些优化执行，无论执行它的上下文的`optimizationLevel`是什么。
